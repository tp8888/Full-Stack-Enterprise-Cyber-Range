# Phase 10: Splunk SIEM Deployment & Telemetry

> **Credit & Inspiration:** This architecture is built based on the "Building a Virtual Security Home Lab" blueprint designed by [David Varghese](https://david-varghese.medium.com/).

## 📌 Objective
To deploy a centralized Security Information and Event Management (SIEM) system capable of ingesting, parsing, and alerting on telemetry generated by the simulated corporate network (`AD_LAB`). 

## ⚙️ SIEM Infrastructure (Splunk Enterprise)
An Ubuntu Server VM was deployed to the `SECURITY` zone with elevated hardware resources (4GB RAM, 100GB Storage) to handle high-volume log indexing. 
* **Deployment:** Splunk Enterprise was installed on the Ubuntu host.
* **Index Creation:** A dedicated index named `windows` was created to isolate and store telemetry originating from the Active Directory environment.

## 📡 Log Ingestion (Universal Forwarder)
To gain visibility into the corporate environment, the **Splunk Universal Forwarder** was installed directly onto the Windows Server 2019 Domain Controller (`AD_LAB` zone). 

The forwarder was configured to push the following critical telemetry across the pfSense firewall and into the Splunk index:
* Application Logs
* Security Logs (Authentication successes/failures)
* System Logs

## 🎯 Verification
Telemetry flow was verified by generating simulated user activity on the Domain Controller (opening applications, failing logins) and querying the Splunk search head (`index="windows"`) to observe the events populating in near real-time. This pipeline establishes the foundation for future Threat Hunting and Alert Generation labs.
